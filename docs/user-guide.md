# CodeAgent 用户指南

## 这是什么

这是一个分析 Python 坏味道并自动修复的智能体（CodeAgent）。它只做**机械性重构**（提取函数、重命名变量），不判断语义正确性。

运行后进入 Review → Reflect → Refactor 循环：
1. **Review** — 扫描代码，检测坏味道，检查语法
2. **Reflect** — 决定先修哪个、用什么手法、要不要重试
3. **Refactor** — 执行修改，重新 Review 检查结果，必要时再 Reflect

整个过程一条命令跑到底，不需要手动干预。

---

## 怎么运行

需要在项目目录下执行：

```bash
cd examples/default
python src/main.py <文件路径|目录路径>
```

支持单个文件或整个目录。不加参数或传 `--help` 会打印用法。

### 运行后会输出什么

```
=== Review: my_code.py ===
  [large-class] my_code.py:1-48  severity=0.65
  [long-function] my_code.py:50-83  severity=0.41

重构 [large-class] → extract-class  (severity=0.65)
  FAIL extract-class 失败，已回退
重构 [long-function] → extract-function  (severity=0.41)
  OK extract-function 已应用

接受：所有坏味道已处理或跳过

=== Done ===
成功: 1 步
失败: 1 步
```

### 它会改我的文件吗

会。工具会直接修改目标文件，不会停下来确认。但每次修改后会自动编译检查，语法不通过会撤销本次修改。

建议先在测试文件上试用。

---

## 它能检测什么

扫描 Python 文件，识别三类坏味道：

| 类型 | 阈值 |
|------|------|
| 过长函数 | 函数体超过 30 行 |
| 过长参数列表 | 参数超过 5 个 |
| 过大类 | 方法超过 10 个，或字段超过 10 个 |

每个检测结果包含位置（文件名:行号）、严重度评分和关键度量值。

注意：如果函数内部嵌套了另一个函数，内外层会被分别检测，可能出现行号范围重叠的重复报告。

---

## 它能修复什么

| 坏味道 | 对应修复 | 当前状态 |
|--------|---------|---------|
| 过长函数 | 提取函数 | ✅ 已实现 |
| 变量名含义不清 | 重命名变量 | ✅ 已实现 |
| 过长参数列表 | （暂无对应修复） | ❌ |
| 过大类 | 提炼类 | ❌ |

检测到但无对应修复手法的坏味道会被 Reflect 阶段跳过，不影响流程。

> 注意：已实现的修复手法基于语法树（AST）分析 + 字符串操作输出，不保证变换后的代码语义正确。输出中 `OK` 仅表示"编译通过"，不代表"代码被正确重构"。AST 仅用于分析阶段（变量引用推断、函数边界识别），不参与代码生成，以保留原始格式。

---

## 安全保证

每次修改后自动运行 `python -m py_compile` 检查语法 + 重新 Review 检测是否引入新坏味道。语法不通过或检测到增量坏味道会提示，但不会自动回滚。

注意：
- **编译检查通过 ≠ 重构正确**。编译通过只说明语法合法，不保证逻辑正确。变换器可能产生语法合法但语义错误的代码（尤其涉及嵌套函数时）
- **单步修改失败会自动回滚，不影响已成功的修改**。
- **成功修改会标记已尝试，避免同一坏味道被反复修复**（无限循环保护）。
- **运行结束后失败的步骤已回滚，成功的步骤保留修改**。

---

## 能力边界

- 只支持 Python。不处理 TypeScript/JavaScript。
- 只处理同一文件内的重构。不涉及跨文件修改。
- 没有交互式界面。不会停下来等你确认。
- 没有 `--dry-run` 等预览参数。`--help` 支持，展示用法后退出。
- 运行结束后不自动还原文件。
